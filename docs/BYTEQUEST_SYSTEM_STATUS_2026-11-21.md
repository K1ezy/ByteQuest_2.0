| Student sign-up (11/21/26) | Students register directly with the School ID issued at enrollment: a two-digit year, a hyphen and a five-digit registration number from `00001`, for example `26-00001`. No admin approval is required. The **Approve student sign-up** panel and `PUT /admin/student-registration-roster` were removed, and migration `20261121060000` stopped the sign-up trigger from reading the old roster table. The table remains, so earlier records are kept. A School ID already held by any account cannot be registered again, and a unique index blocks two simultaneous student sign-ups with one ID. **Continue** runs every credential check before the Terms step: username format and availability, email format, an 8-character minimum password, School ID format and availability, year level and block. The School ID check uses `POST /profile/school-id-availability` and is capped at 60 requests a minute across all users, because the hosted API sees the proxy's address rather than each learner's. Trade-off: the first person to register an ID owns it, so an admin must correct any ID registered by the wrong person. Email confirmation is temporarily off in local Supabase (`enable_confirmations = false` in `supabase/config.toml`), so a new account signs in immediately; a test sign-up on 11/21/26 returned a session at once. The hosted Supabase project has its own setting, which this does not change. Verified with backend and frontend tests on 11/21/26.
