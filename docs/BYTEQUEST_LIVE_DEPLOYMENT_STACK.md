## What to pay for

**For the 24/7 live pilot with the Gemini chatbot, budget for one Hostinger KVM 2 VPS, one domain, one Supabase Pro project and Gemini Developer API usage**, subject to Google's age and data terms. Self-host Judge0 on the VPS. Use Vercel Hobby for Next.js if the deployment meets its personal, non-commercial terms and usage limits. For a university-owned deployment, confirm institutional requirements and consider running Next.js on the VPS behind Caddy. Use the existing Supabase Free project for synthetic rehearsal. Choose Pro for the real class because it stays available between sessions and includes managed database recovery for accounts and grades. ## Before the 30-student session

1. **Connect the full hosted path.** Point the frontend and API names to their respective hosts. Build `frontend/` with the three `NEXT_PUBLIC_*` production values, configure exact HTTPS CORS origins and Supabase Auth redirect URLs, and apply the reviewed migrations. The current Compose file has no Next.js service; a VPS-only deployment needs a production Next.js build/service and a Caddy frontend route. Exercise student, instructor and admin access with synthetic identities, including course boundaries and shared-workstation sign-out. [Frontend environment](../frontend/.env.production.example) · [Backend environment](../infra/backend.prod.env.example) · [VPS Compose](../infra/docker-compose.yml) · [Deployment readiness](PHASE7_DEPLOYMENT_READINESS.md)
2. **Keep code execution private.** Publish Caddy for app traffic and keep Judge0's API, Redis and PostgreSQL on their internal networks with sandbox networking disabled. Check the reviewed Judge0 image and host setup against upstream security guidance. Judge0 containers are privileged in this Compose setup, so sharing the VPS with the API means sharing a host risk. A private dedicated runner host is a later option if institutional policy or public, unsupervised access requires a stronger boundary. [VPS Compose](../infra/docker-compose.yml) · [Judge0 production settings](../infra/judge0.conf.example) · [Judge0 advisories](https://github.com/judge0/judge0/security/advisories)
3. **Reconcile the grading settings and measure a class-sized burst.** The example allows two API processes at `4 + 4` connections each and the Compose worker `5 + 5`, for a ceiling of **26** against the example budget of **20**. The preflight still counts only **2** worker connections. Judge0's example sets `COUNT=3` while its comment suggests one execution slot on a shared two-vCPU VPS. Align the configured pool limits and checker, then measure API p95, queue wait, grading p95, errors, CPU, memory and disk with 30 synthetic students submitting and finalizing exams across the pilot languages. Watch the application worker heartbeat and sandbox checks separately. Move to KVM 4 when the hosted test demonstrates a CPU or queue bottleneck that safe tuning cannot meet. [VPS preflight](../infra/preflight-vps.sh) · [VPS Compose](../infra/docker-compose.yml) · [Backend example](../infra/backend.prod.env.example) · [Judge0 example](../infra/judge0.conf.example) · [Release test plan](SYSTEM_STATUS_AND_RELEASE_PLAN.md) · [Pilot monitoring](PILOT_OPERATOR_RUNBOOK.md)
4. **Decide which optional workflows are in scope.** With Gemini disabled, use pre-authored coursework and standard quiz and code grading; tutor responses, AI drafts and embedding new PDFs are unavailable. Without configured Auth SMTP, existing confirmed accounts can sign in, but class-wide confirmation, invitations and self-service recovery require an approved provisioning and recovery plan. ByteQuest's separate outbound exam email can stay off while the class uses in-app notices. Keep shadow scoring and research collection disabled until the required approvals and individual consent are in place. [Gemini client](../backend/app/services/ai_rag/gemini_client.py) · [PDF indexing](../backend/app/services/materials.py) · [Account invitation](../backend/app/services/account_provisioning.py) · [Pilot scope](SYSTEM_STATUS_AND_RELEASE_PLAN.md) · [Operator runbook](PILOT_OPERATOR_RUNBOOK.md)
5. **Rehearse recovery before real accounts or grades depend on it.** Verify the database and Auth recovery path in a separate synthetic project, export private Storage files separately, and keep an approved encrypted offsite copy and protected deployment configuration. Supabase database backups include Storage metadata only, so schedule a separate PDF export even with Pro. Establish who watches VPS resources, readiness, queue age and failed grading jobs during the session.
