# ByteQuest repository guidance

- **System status** Read the [system status log](docs/BYTEQUEST_SYSTEM_STATUS_2026-11-21.md) for implemented features, running services, Git state, verification and open release checks. When you change behaviour, update that log as it says at its top: one dated row per area, with stale rows replaced rather than duplicated.
- **Codebase exploration** Follow the [graphify workflow](CLAUDE.md#graphify). Read [frontend guidance](frontend/AGENTS.md) before editing the Next.js app.
- **Hosted pilot** Use the [KVM 2 checklist](docs/KVM2_LIVE_PILOT_CHECKLIST.md) and [release gates](docs/SYSTEM_STATUS_AND_RELEASE_PLAN.md#5-six-gates-before-a-live-classroom-pilot) for deployment work and acceptance evidence.
- **Latest checkpoint** Start with the [28–29 November 2026 checkpoint](docs/handoff/CODEX_CHECKPOINT_2026-11-28.md): students have no language track (Workshops decide what they see), and charts and metrics lead with plain sentences ([ADR 0001](docs/adr/0001-workshops-decide-what-students-see.md)). Use the vocabulary in [GLOSSARY.md](GLOSSARY.md).
